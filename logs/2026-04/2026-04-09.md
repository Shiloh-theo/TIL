## 1. Why You Never Ask the User for Their Own Account Number

If the frontend sends the sender's account as a form field, any user can modify it in DevTools and send money from someone else's account. The secure pattern: extract the sender's account from the validated JWT on the backend. The user cannot tamper with what they never touch.

```java
@GetMapping("account")
public ResponseEntity<?> getAccount(@RequestHeader("Authorization") String authHeader) {
    String token = authHeader.substring(7); // strips "Bearer "
    String email = jwtUtil.extractEmail(token);
    Accounts account = accountService.getAccountDetails(email);
    if (account == null) return ResponseEntity.status(HttpStatus.NOT_FOUND).body("Not found");
    return ResponseEntity.ok(account);
}
```

## 2. DEBIT/CREDIT Type Computed in Service Layer

The transaction table stores sender and receiver account numbers. Whether a transaction is a DEBIT or CREDIT depends on who is asking. Computed in the service — never stored as a column:

```java
String type = tx.getSenderAccount().equals(accountNo) ? "DEBIT" : "CREDIT";
```

`findBySenderAccountOrReceiverAccount` — Spring Data JPA generates the SQL query automatically from the method name. No @Query needed.

## 3. Why Spring Security Blocked CORS Even With CorsConfig Correct

Browsers send a preflight OPTIONS request before every cross-origin POST/PUT. Spring Security intercepted these OPTIONS requests and rejected them before they ever reached CorsConfig.

**Fix:** Add `.cors(Customizer.withDefaults())` as the FIRST rule in SecurityFilterChain:

```java
http
    .cors(Customizer.withDefaults()) // process CORS first
    .csrf(csrf -> csrf.disable())
    .authorizeHttpRequests(auth -> auth
        .requestMatchers("/bank/register", "/bank/login").permitAll()
        .anyRequest().authenticated()
    )
```

This tells Spring Security to delegate CORS to the CorsConfigurationSource bean — which CorsConfig already provides correctly.

## 4. Why the Module-Level Variable Pattern in api.js

Axios interceptors are registered once when the module loads — outside the React component lifecycle. They cannot read React Context or useState directly.

**Solution:** A plain JS module variable the interceptor can always access:

```javascript
let authToken = null;

export const setAuthToken = (token) => { authToken = token; };

api.interceptors.request.use((config) => {
    if (authToken) config.headers.Authorization = `Bearer ${authToken}`;
    return config;
});
```

AuthContext calls `setAuthToken(token)` on login and `setAuthToken(null)` on logout. The interceptor always reads the current value.

## 5. Why parseFloat Is Needed on Transfer Form Input

HTML inputs always return strings. `"5000"` is not `5000`. JavaScript has no BigDecimal — `parseFloat` converts the string to a JS number, Axios serializes it as a JSON number, Spring Boot deserializes it to BigDecimal on the backend.

```javascript
amount: parseFloat(formData.amount) // "5000" → 5000 → BigDecimal on backend
```

## 6. Argument Order Bug — A Classic

`login()` was defined as `login(token, email)` but called as `login(email, token)`. The token was stored as the user's email and the email was stored as the token. Welcome message showed nothing. JWT interceptor attached a corrupt header. Everything silently broke.

**Lesson:** Argument order bugs are invisible — no compile error, no runtime crash. Always double-check call sites match definitions when debugging auth issues.

## 7. PrivateRoute Pattern

Protects authenticated routes using React Router's `Outlet`:

```jsx
function PrivateRoute() {
    const { token } = useAuth();
    return token ? <Outlet /> : <Navigate to="/login" />;
}

// In App.jsx:
<Route element={<PrivateRoute />}>
    <Route path="/dashboard" element={<DashboardPage />} />
    <Route path="/transfer" element={<TransferPage />} />
    <Route path="/history" element={<TransactionHistoryPage />} />
</Route>
```

If no token, user is redirected to login. After login, they land on dashboard. Clean, reusable, secure.

## 8. UX Patterns Built Today

- Sender account auto-fetched and shown as read-only — user never types their own account
- Button disabled until account loads — prevents empty sender submission
- 1.5 second delay then navigate to dashboard after successful transfer
- `err.response?.data` surfaces backend error messages directly to UI
- `tx.time?.substring(0, 5)` trims timestamp to HH:mm for clean display
- Empty state shown when no transactions exist
