## Lesson 7 — application.properties + CORS

### application.properties
Spring Boot reads this file on startup to configure the entire application.

```properties
# Database connection
spring.datasource.url=jdbc:postgresql://localhost:5432/ledger_db
spring.datasource.username=postgres
spring.datasource.password=yourpassword

# JPA/Hibernate
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.PostgreSQLDialect

# Server port
server.port=8080
```

### Why show-sql=true matters
Every SQL query JPA generates gets printed to the console. Essential for debugging — you can see exactly what Hibernate is running against your database, catch N+1 problems, and verify your queries are correct.

### CORS (Cross-Origin Resource Sharing)
By default browsers block requests from one origin (e.g. localhost:3000 React app) to a different origin (localhost:8080 Spring Boot). CORS configuration tells the backend which origins are allowed.

```java
@Configuration
public class CorsConfig {
    @Bean
    public WebMvcConfigurer corsConfigurer() {
        return new WebMvcConfigurer() {
            @Override
            public void addCorsMappings(CorsRegistry registry) {
                registry.addMapping("/**")
                    .allowedOrigins("http://localhost:3000")
                    .allowedMethods("GET", "POST", "PUT", "DELETE")
                    .allowedHeaders("*");
            }
        };
    }
}
```

Without this, the React frontend cannot talk to the Spring Boot backend — every request gets blocked by the browser.

## Lesson 8 — Docker

### Why Docker
"Works on my machine" is not acceptable in production. Docker packages the application and all its dependencies into a container that runs identically everywhere — your laptop, a server, a colleague's machine.

### Dockerfile
```dockerfile
FROM eclipse-temurin:22-jdk
WORKDIR /app
COPY target/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

Line by line:
- `FROM eclipse-temurin:22-jdk` — base image with Java 22 already installed
- `WORKDIR /app` — set working directory inside the container
- `COPY target/*.jar app.jar` — copy the built Spring Boot jar in
- `EXPOSE 8080` — document which port the app uses
- `ENTRYPOINT` — command to run when the container starts

### docker-compose.yml
Orchestrates both containers (Spring Boot + PostgreSQL) together:

```yaml
version: '3.8'
services:
  db:
    image: postgres:15
    environment:
      POSTGRES_DB: ledger_db
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: yourpassword
    ports:
      - "5432:5432"

  app:
    build: .
    ports:
      - "8080:8080"
    depends_on:
      - db
    environment:
      SPRING_DATASOURCE_URL: jdbc:postgresql://db:5432/ledger_db
      SPRING_DATASOURCE_USERNAME: postgres
      SPRING_DATASOURCE_PASSWORD: yourpassword
```

Key insight: `db` in the datasource URL refers to the service name in docker-compose — Docker's internal DNS resolves it automatically. The app container waits for the db container via `depends_on`.

Build and run:
```bash
mvn clean package -DskipTests
docker-compose up --build
```

## Lesson 9 — JWT Authentication

### What JWT is
JSON Web Token — a self-contained, signed token that proves who you are. Three parts separated by dots:
- **Header** — algorithm used (HS256)
- **Payload** — claims: userId, email, expiry time
- **Signature** — HMAC hash of header + payload using a secret key

The server signs it on login. The client sends it with every subsequent request. The server verifies the signature — no database lookup needed.

### Why the same JWT works for web AND mobile
It's just a string in an HTTP header: `Authorization: Bearer <token>`. The Spring Boot backend doesn't know or care whether the caller is a React browser app or a React Native mobile app. Same token, same validation.

### Three files built:

**JwtUtil.java** — generates and validates tokens
```java
public String generateToken(String email) {
    return Jwts.builder()
        .setSubject(email)
        .setIssuedAt(new Date())
        .setExpiration(new Date(System.currentTimeMillis() + 86400000)) // 24hrs
        .signWith(SignatureAlgorithm.HS256, SECRET_KEY)
        .compact();
}
```

**JwtFilter.java** — intercepts every request, extracts and validates the token
```java
// Extends OncePerRequestFilter
// Reads Authorization header
// Validates token via JwtUtil
// Sets authentication in SecurityContext if valid
```

**SecurityConfig.java** — defines which endpoints are public vs protected
```java
// /bank/register and /bank/login → public (no token needed)
// Everything else → requires valid JWT
```

### Flow
```
User logs in → backend verifies password → issues JWT
User sends request → JwtFilter intercepts → validates token → allows/denies
```
